# C4.9 技术设计：Winner Lifecycle 多 Replicate 与人工复核矩阵

> 所属系列：[冲突检测 V2 里程碑规划](冲突检测V2-里程碑规划.md)
>
> 状态：**研究实验工具已实现，待真实 Linux 服务运行**。
>
> 不新增 migration；依赖已冻结的 C4.6 proposal、C4.7 durable adoption、C4.8 reopen。

---

## 1. 目标

C4.6/C4.7/C4.8 的单次真实服务回归已经通过，但单个 run 不能说明：

```text
不同独立执行是否仍得到正确 winner/no-winner policy
不同文档摄取顺序是否会泄漏 raw A/B orientation
adopt → reopen → re-adopt 生命周期是否可重复
issuer mismatch、日期/version 信号不一致、并列版本能否稳定 fail closed
```

C4.9 新增一个**无 UI、脚本驱动、真实服务**的 matrix runner：

```text
matrix cases × independent replicates
→ public HTTP manual ingest
→ real Asynq claim/detection
→ PostgreSQL read-only evidence export
→ C4.7 explicit adoption / C4.8 explicit reopen
→ structured matrix + reviewer CSV
```

它不写 PostgreSQL；所有 mutation 均由既有 public API 实施。

---

## 2. Replicate 不等于模型 seed

当前 provider/model API 没有跨模型可移植的随机 seed 控制。因此 C4.9 故意使用：

```text
independent replicate
```

而不是声称“multi-seed experiment”。每个 replicate 创建全新的 temporary KB、全新的 manual documents
和全新的 Asynq tasks；报告记录独立运行结果、raw conflict count 波动和 case pass rate，但不会把重复运行
夸大为受控 RNG 因果实验。

若某个具体 provider 后续支持稳定 seed，必须在 HTTP payload、run manifest 和 matrix 中显式记录；在此之前
`seed_control = none; independent replicates only` 是唯一有效表述。

## 3. 默认 controlled policy matrix

默认配置：

```text
scripts/experiments/scenarios/c49_winner_lifecycle_matrix.json
```

| Case | Metadata / ingest order | Gold policy | Action coverage |
|---|---|---|---|
| `ordered_triplet_two_cycles` | 同 issuer V1 → V2 → V3 | V3 唯一 winner | 两轮 adopt → reopen，验证 explicit re-adoption |
| `out_of_order_triplet` | 同 issuer V3 → V1 → V2 | V3 唯一 winner | raw A/B 方向与版本顺序脱钩后 adopt → reopen |
| `cross_issuer_no_proposal` | issuer 不同、日期/version 可比 | 无 proposal | C4.7 adoption 409 + C4.8 reopen 409 |
| `date_version_disagreement_no_proposal` | issuer 相同，日期与版本方向相反 | 无 proposal | 两个 no-action guards |
| `date_version_tie_no_proposal` | issuer 相同，日期/版本相等 | 无 strict maximum | 两个 no-action guards |

每个 case 都复用 `run_claims_eval.py` 的 document-pair、cluster count、anchor kind 和 winner count
断言，并将 `dead_letter_count != 0` 视为 case failure。raw chunk-pair 数量可以在独立运行间变化；
C4.9 不将它误当作事实层 gold 数量。

默认语料是**controlled policy corpus**，不是外部真实法规/产品语料，不能用其 P/R 声称业务文档泛化。

## 4. 运行与产物

```bash
# 默认每个 case 做 3 个独立 replicate
make experiment-c49

# 显式指定次数
make experiment-c49 REPLICATES=5

# 自定义 matrix 与输出目录
make experiment-c49 \
  REPLICATES=3 \
  MATRIX=/absolute/path/to/my_winner_matrix.json \
  OUTPUT=experiments/comparisons/my-winner-matrix
```

runner 首先执行：

```text
run_claims_eval.py --check --check-db
```

所以会要求 C4.8 PostgreSQL `000092` schema 已就绪。每个 case/replicate 输出隔离目录：

```text
experiments/comparisons/<matrix-run>/
├── matrix_manifest.json
├── environment_check.txt
├── matrix_results.json
├── matrix_summary.json
├── matrix_summary.md
├── winner_lifecycle_review.csv
└── replicates/<case>/replicate-XX/
    ├── detector/                    # normal run_claims_eval artifacts
    ├── detector_output.txt
    ├── adoption_cycle_N.txt
    ├── reopen_cycle_N.txt
    └── case_result.json
```

其中正例 cycle 使用独立的：

```text
detector/c49_adoption_cycle_N.json
detector/c49_reopen_cycle_N.json
```

负例使用：

```text
detector/c49_adoption_negative.json
detector/c49_reopen_negative.json
```

这些目录都位于现有 Git-ignored `experiments/comparisons/` 下。

## 5. 指标与人工复核出口

`matrix_summary.json` 输出：

```text
case_pass_rate
proposal_policy_matrix:
  expected_positive / expected_no_proposal
  true_positive / false_positive / false_negative
  precision / recall
lifecycle_cycles:
  expected / fully_passing_case_cycles / pass_rate
raw_conflict_count:
  min / max / mean
dead_letter_count:
  total / max / all_zero
seed_control = none; independent replicates only
```

`proposal_policy_matrix` 仅针对默认或用户提供的**明确标签 matrix**。它是 policy/integration correctness
指标，不是 Claim P/R，也不是外部真实文档上的模型准确率。

`winner_lifecycle_review.csv` 每个 case/replicate 一行，保留双审阅与仲裁列：

```text
reviewer_1_label / reviewer_1_note
reviewer_2_label / reviewer_2_note
adjudicated_label / adjudicated_note
```

用于两个独立审阅者对自定义真实语料执行人工复核。建议标签：

```text
correct_winner
correct_no_proposal
wrong_winner
missed_winner
unsafe_action
uncertain
```

填写后运行：

```bash
make experiment-c49-review REVIEW=experiments/comparisons/<c49-run>/winner_lifecycle_review.csv
```

它输出 completion、双审阅 exact agreement、Cohen's kappa、仲裁后的 manual policy accuracy，并且将空白、
`uncertain`、`exclude`、未仲裁的 disagreement 排除在 accuracy 分母之外。

对真实语料的正式论文数字应报告：语料来源/许可、标注协议、至少两位审阅者、一致性、拒绝/不可比样本，以及
独立 holdout。C4.9 summary 不会自动把默认 controlled CSV 汇总结果称为真实语料“人类准确率”。

## 6. 自定义真实语料 matrix 格式

用户可复制默认 matrix，将每个 case 的 `scenario` 指向已有格式的 `run_claims_eval` scenario：

```json
{
  "name": "my_winner_matrix",
  "variant": "c2-rules",
  "cases": [
    {
      "id": "real_policy_triplet",
      "scenario": "scripts/experiments/scenarios/my_real_triplet.json",
      "expected_outcome": "adopt_reopen",
      "expected_winner_document": "revision_2026_03",
      "adoption_cycles": 1
    },
    {
      "id": "real_cross_issuer",
      "scenario": "scripts/experiments/scenarios/my_cross_issuer.json",
      "expected_outcome": "no_proposal"
    }
  ]
}
```

正例最多允许 3 个 adoption cycles；每轮都先 stale-reject，再精确 adopt/reopen。负例自动调用 C4.7
`--expect-no-proposal` 和 C4.8 `--expect-no-active-adoption`，并要求 HTTP `409` / no mutation。

## 7. 关闭条件

C4.9 在真实服务运行后才可冻结。应至少确认：

- [ ] `REPLICATES >= 3` 的默认 matrix 全部通过；
- [ ] ordered 与 out-of-order 正例都始终得到预期 V3 winner；
- [ ] 两轮 adoption/reopen cycle 保持 durable record / pending reopen invariant；
- [ ] cross-issuer、date/version disagreement、tie 负例均为 zero proposal + 409/no mutation；
- [ ] 15 个 detector run 的 dead_letter_count 均为 0，并已汇总到 matrix summary；
- [ ] matrix summary、双审阅 review CSV / review summary 和逐 replicate artifacts 已导出；
- [ ] 结果明确标为 controlled policy matrix，不混同真实语料/human accuracy；
- [ ] 真实外部语料与双审阅协议仍为后续独立研究。
