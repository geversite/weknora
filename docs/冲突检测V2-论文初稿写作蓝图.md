## 1. 建议的论文中心问题

不要把论文问题写成“企业文档冲突检测的通用高准确率”。更稳妥的研究问题是：

> 在版本化、多来源知识库中，如何将 raw chunk-pair conflict 提升为可审计的事实级 DisputedFact，并在显式 issuer/date/version evidence 下安全地提出全局 winner，随后通过显式、可撤销的 adoption/reopen 生命周期避免局部 A/B 方向造成错误全局副作用？

可用中文标题候选：

```text
从块对冲突到可撤销的事实级治理：面向版本化多来源知识库的安全 Winner Proposal
```

可用英文工作标题：

```text
From Chunk-Pair Conflicts to Reversible Fact-Level Governance in Versioned Knowledge Bases
```

## 2. 论文可主张与不可主张

### 可主张

```text
1. 提出一个从 claim extraction、candidate cascade、DisputedFact clustering 到 global winner proposal 的研究原型。
2. 将 winner side effect 限制为 explicit-only，并通过 snapshot、durable adoption record 和 precise reopen 实现 fail-closed。
3. C2 cascade 在既有真实服务消融中降低 LLM 调用/Token/延迟。
4. C4.6/C4.7/C4.8 在 controlled real-service matrix 中完成 proposal、adoption、reopen 与 no-action guards。
5. C4.10 synthetic holdout 显示 global all-source rule 在构造的 issuer/date/version failure modes 下避免了简化 baseline 的 unsafe proposal。
```

### 不可主张

```text
1. 对真实业务文档具有普遍 winner/detection accuracy。
2. 已解决任意 authority hierarchy、跨机构权威关系或复杂版本语义。
3. PDF↔DOCX 跨格式事实聚类准确率已被充分验证。
4. 已证明真实人工工时节省或生产用户价值。
5. 结果具有 provider RNG seed-controlled 因果可重复性。
6. synthetic holdout 等价于真实 corpus 或双审阅 human study。
```

## 3. 推荐论文结构

### 3.1 Introduction

建议四段结构：

1. **问题动机**：现有 KB conflict 多停留在 chunk-pair，无法自然表达“多个来源围绕同一事实”的争议；
2. **安全缺口**：raw A/B 的 `newer/older` 方向不是全局 winner，直接传播会误禁用仍应保留的来源；
3. **方法概述**：claim anchor、cascade、DisputedFact、global proposal、explicit adoption/reopen；
4. **贡献列表**：四项贡献与明确 scope boundary。

可直接使用的贡献表述：

```text
(1) 一个把 raw chunk-pair conflict 投影为 DisputedFact 的事实级冲突治理模型；
(2) 一个 claim-aware candidate cascade，在规则层和 grounded batch LLM 间控制成本；
(3) 一个要求所有 cluster sources 共同满足显式 metadata 一致性的 global winner proposal；
(4) 一个 explicit-only、optimistic、durable、可 precise-reopen 的 winner lifecycle protocol。
```

### 3.2 Problem Formulation

定义以下对象即可，不要过度形式化 authority hierarchy：

```text
Claim = (subject, predicate, value, qualifiers, quote)
ClaimKey = normalize(subject, predicate)
RawConflict = chunk-pair / claim evidence pair
DisputedFact = (fact_key, sources, candidate_values, raw_conflict_members)
WinnerProposal = (winner source, metadata evidence, confidence, version)
WinnerAdoption = explicit snapshot-bound side effect
WinnerReopen = durable-record-bound reversal
```

关键安全不变量：

```text
- 无 proposal 不可 adopt；
- stale proposal 不可 adopt；
- raw pair direction 不可直接解释为 global winner；
- reopen 只重启 durable record 精确记录的 loser chunks；
- metadata missing / issuer mismatch / tie / signal disagreement 必须 abstain。
```

### 3.3 System Design

建议配一张主图：

```text
Document / Wiki
  → C1 Claim extraction
  → exact ClaimKey candidate + fallback
  → C2 rules / grounded batch LLM
  → raw KnowledgeConflict
  → C4 DisputedFact clustering
  → C4.6 global proposal
  → C4.7 explicit adoption
  → C4.8 durable reopen
```

将以下设计强调为“安全边界”而非“自动治理”：

```text
proposal ≠ adoption
adoption ≠ irreversible deletion
reopen ≠ automatic re-adoption
```

### 3.4 Evaluation

建议拆成四部分：

```text
E1. Claim extraction / candidate coverage（C1）
E2. Cascade cost ablation（C2）
E3. Fact clustering and lifecycle safety（C4.6–C4.9）
E4. Binary file integration + expanded synthetic development/holdout policy evaluation（C4.10）
```

### 3.5 Limitations / Threats to Validity

必须单独成节，避免审稿人将 controlled result 误读为现实泛化：

```text
- C1 审计为 development/calibration，且以 single reviewer 为主；
- C4.9 是 controlled policy matrix，非真实业务语料；
- C4.10 的 extended holdout 为确定性 synthetic corpus；
- PDF 只完成 file ingress / claim smoke，不等于跨格式 clustering benchmark；
- 没有 portable provider seed；
- 没有真实 authority hierarchy 或双审阅 human study。
```

## 5. Results 段落模板

可以使用如下写法，但不要删掉限定词：

> 在扩展的 controlled synthetic holdout 中，我们对 12 个未参与 development 调试的事实家族执行了 3 次 independent replicate，共 36 个 case executions。所有 detector artifact 完整且 `dead_letter_count=0`，C4.6 global proposal 在 18 个正例和 18 个 no-proposal 负例上分别得到 18 TP 和 18 TN；18 次 explicit adoption/reopen lifecycle 均完成。按“同一事实家族的所有 replicate 都正确”这一严格口径，C4.6 的 policy accuracy 为 1.000，unsafe action 为 0。相比之下，latest-upload、date-only、version-only 与 raw C3 local vote 在构造的跨 issuer、metadata 缺失、信号不一致和 tie 模式中产生了 6、3、3、2 个 unsafe fact-family actions。该结果说明 global all-source consistency rule 能在本受控 policy corpus 中避免局部或单信号启发式的错误 winner proposal；它不构成对真实业务文档泛化能力的估计。
