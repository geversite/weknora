## 1. 先生成可编辑 SVG

五张图均可由纯 Python 标准库脚本生成，不依赖 Graphviz、Matplotlib、浏览器或图像模型：

```bash
cd ~/weknora

FIGURE_OUT="$HOME/weknora-paper-assets/conflict-v2-figures"
mkdir -p "$FIGURE_OUT"

make paper-figures \
  FIGURE_OUTPUT="$FIGURE_OUT"
```

生成：

```text
fig1_system_architecture.svg
fig2_fact_lifecycle.svg
fig3_cascade_cost_ablation.svg
fig4_holdout_baselines.svg
fig5_fail_closed_state_machine.svg
figures_manifest.json
README.md
```

SVG 是矢量图，可用 Inkscape、Figma、Illustrator、draw.io 或浏览器打开。若本机安装 Inkscape，可转为 PDF：

```bash
cd "$FIGURE_OUT"
inkscape fig1_system_architecture.svg --export-type=pdf
```

IEEE LaTeX 初稿可直接 staging 这些 SVG：

```bash
cd ~/weknora/paper/ieee
make figures FIGURE_SOURCE="$FIGURE_OUT"
make pdf
```

若目标 conference 禁止 LaTeX shell escape，则先生成 PDF fallback：

```bash
make figures FIGURE_SOURCE="$FIGURE_OUT" CONVERT_PDF=1
make pdf
```

脚本数据来源：

```text
图 3：接地级联相对全量 LLM 的成本消融
图 4：合成策略 holdout 的 fact-family 主口径
图 1/2/5：冻结的架构与 fail-closed 协议
```

不要把图 4 的 controlled-synthetic scope footer 裁掉；若按 venue 样式去掉 footer，必须在图注保留同等限定。

## 2. 图表清单与论文位置

| 图 | 文件 | 正文位置 | 图注核心 |
|---|---|---|---|
| 图 1 | `fig1_system_architecture.svg` | 第 3 节开头 | 从 claim extraction 到 explicit、可撤销 winner lifecycle 的系统架构 |
| 图 2 | `fig2_fact_lifecycle.svg` | 第 3.3–3.5 节 | 多条 raw conflicts 聚成一个 DisputedFact，局部方向不直接成为全局 action |
| 图 3 | `fig3_cascade_cost_ablation.svg` | 第 5.3 节 | Grounded cascade 相对 All-LLM 的 LLM calls、Token 与时延成本消融 |
| 图 4 | `fig4_holdout_baselines.svg` | 第 5.6 节 | Global proposal 与 latest/date/version/local-vote baseline 的 policy accuracy 与 unsafe actions |
| 图 5 | `fig5_fail_closed_state_machine.svg` | 第 3.5 节或第 6 节 | proposal、explicit adoption、durable reopen 与 HTTP 409 fail-closed 分支 |

### 建议图注

**图 1：** WeKnora fact-level conflict governance. Claims are extracted from documents and wiki pages, passed through exact and fallback candidate channels, adjudicated by a rule-plus-grounded-LLM cascade, and clustered into DisputedFacts. Winner proposals are advisory; adoption and reopen are explicit, snapshot-bound, and reversible.

**图 2：** Three versioned sources yield three raw pair conflicts but one DisputedFact. A global proposal is issued only when all-source issuer/date/version evidence is consistent and a unique strict maximum exists. Adoption and reopen are explicit, auditable operations.

**图 3：** On the same controlled full scenario, the grounded cascade reduces LLM calls from 48 to 9 and also reduces tokens and detection latency relative to an all-LLM baseline. This is a real-service cost ablation on a fixed scenario, not average document cost.

**图 4：** On 12 constructed synthetic holdout fact families, the global all-source proposal is compared with recency and local-vote baselines. A family counts as correct only if all three independent replicates are correct. This is not real-business-document accuracy.

**图 5：** Fail-closed state machine for advisory proposal, explicit adoption, and durable reopen. Any metadata, snapshot, member-topology, or target-state mismatch returns HTTP 409 with no mutation.

## 3. 统一视觉规范

建议所有图保持：

```text
画布：白底，横向 16:9 或 A4 双栏宽度
字体：Noto Sans CJK SC / 思源黑体 / Microsoft YaHei（IEEE 终稿用 Helvetica / Arial）
主文字：深蓝 #17324D
claim / architecture：蓝 #2878B5
metadata / proposal：青绿 #1E9E89
explicit action：橙 #ED8A19
fail-closed / unsafe：红 #D95D54
reopen / durable record：紫 #7664C5
```

避免：

```text
3D 图标、人物、拟物化数据库、复杂渐变、过多阴影、彩虹色、长段落文字、无法编辑的截图。
内部研究阶段代号（不要写在任何框、轴、图例或脚注里）。
```

优先使用：

```text
圆角矩形 + 清晰箭头 + 少量图标 + 可读的标签 + 数据来源/范围脚注。
```

## 4. IEEE English redraw prompts (GPT / image model)

Use these **only** for schematic figures (Figs. 1, 2, 5). For Figs. 3 and 4, prefer the Python SVG script: image models distort bar heights. If you still need a sketch, the chart prompts are at the end of this section.

Shared constraints for every prompt. Paste them first, then one figure prompt.

```text
IEEE conference figure for two-column insertion. English only. No title inside the image (LaTeX caption exists). White background, flat 2D vector schematic, tight layout, almost no unused margin. Aspect ratio 2.35:1, as if 7.16 inches wide and 3.05 inches tall. Helvetica or Arial. Body labels 8–9 pt equivalent, secondary labels 7 pt. Thin 1.0–1.25 pt strokes. Corner radius 4 px. No 3D, no people, no photos, no icons of computers/clouds/brains, no drop shadows, no gradients, no glow, no decorative illustrations, no watermark, no outer frame around the canvas. Limited palette: ink #17324D, muted #5F6B7A, blue #2878B5, teal #1E9E89, orange #ED8A19, purple #7664C5, red #D95D54, fills 12% opacity of the same hues. One row of boxes unless a second row is required. Short labels, 1–3 lines max per box. Arrows are simple polylines with small filled triangular heads. Print-safe: every color also has a text label so grayscale still works. Do not print internal research codes, sprint numbers, or ticket IDs anywhere.
```

### Fig. 5 — fail-closed state machine

```text
Compact left-to-right state machine, four states in one row, diamonds only 36 px tall.

States (rounded rectangles):
1. Blue "Pending" — members pending, chunks on
2. Teal "Proposal" — advisory winner + snapshot
3. Purple "Adopted" — winner on, losers off, durable record
4. Blue "Reopened" — pending again, record revoked

Decisions (small diamonds):
D1 between 1 and 2: "unique max + consistent metadata?"
D2 between 2 and 3: "explicit adopt, snapshot match?"
D3 between 3 and 4: "explicit reopen, record match?"

YES arrows go forward. From Reopened a dashed arrow returns under the row to Pending.

NO arrows all go down to one shared red box spanning the bottom:
"HTTP 409 · no mutation
(no proposal / stale / topology change / target mismatch)"

D1 NO also labels "abstain". No other text. No legend. No title. Keep vertical size under 2.4 inches at 7.16 in width.
```
