## 1. 先生成可编辑 SVG

五张图均可由纯 Python 标准库脚本生成，不依赖 Graphviz、Matplotlib、浏览器或图像模型：

```bash
cd ~/weknora

FIGURE_OUT="$HOME/weknora-paper-assets/conflict-v2-figures"
mkdir -p "$FIGURE_OUT"

make paper-figures \
  FIGURE_OUTPUT="$FIGURE_OUT"
```

生成：

```text
fig1_system_architecture.svg
fig2_fact_lifecycle.svg
fig3_cascade_cost_ablation.svg
fig4_holdout_baselines.svg
fig5_fail_closed_state_machine.svg
figures_manifest.json
README.md
```

SVG 是矢量图，可用 Inkscape、Figma、Illustrator、draw.io 或浏览器打开。若本机安装 Inkscape，可转为 PDF：

```bash
cd "$FIGURE_OUT"
inkscape fig1_system_architecture.svg --export-type=pdf
```

IEEE LaTeX 初稿可直接 staging 这些 SVG：

```bash
cd ~/weknora/paper/ieee
make figures FIGURE_SOURCE="$FIGURE_OUT"
make pdf
```

若目标 conference 禁止 LaTeX shell escape，则先生成 PDF fallback：

```bash
make figures FIGURE_SOURCE="$FIGURE_OUT" CONVERT_PDF=1
make pdf
```

脚本数据来源：

```text
图 3：C2-B4 final cost ablation
图 4：C4.10 extended synthetic holdout 的 fact-family 主口径
图 1/2/5：冻结的 C1→C4.8 架构和安全协议
```

不要把图 4 的 controlled-synthetic scope footer 裁掉；若按 venue 样式去掉 footer，必须在图注保留同等限定。

## 2. 图表清单与论文位置

| 图 | 文件 | 正文位置 | 图注核心 |
|---|---|---|---|
| 图 1 | `fig1_system_architecture.svg` | 第 3 节开头 | 从 claim extraction 到 explicit、可撤销 winner lifecycle 的系统架构 |
| 图 2 | `fig2_fact_lifecycle.svg` | 第 3.3–3.5 节 | 多条 raw conflicts 聚成一个 DisputedFact，局部方向不直接成为全局 action |
| 图 3 | `fig3_cascade_cost_ablation.svg` | 第 5.3 节 | C2-B4 相对 C1 的 LLM calls、Token 与时延成本消融 |
| 图 4 | `fig4_holdout_baselines.svg` | 第 5.6 节 | C4.6 与 latest/date/version/local-vote baseline 的 policy accuracy 与 unsafe actions |
| 图 5 | `fig5_fail_closed_state_machine.svg` | 第 3.5 节或第 6 节 | proposal、explicit adoption、durable reopen 与 HTTP 409 fail-closed 分支 |

### 建议图注

**图 1：** WeKnora Conflict Detection V2 的事实级冲突治理架构。系统将文档/Wiki 内容抽取为 claims，经精确和 fallback 候选、C2 cascade 裁决生成 raw conflicts，再聚合为 DisputedFacts。C4.6 的 proposal 无副作用；C4.7/C4.8 的 action 仅在显式 snapshot 与 durable record 条件下执行。

**图 2：** 三个版本来源的三条 raw conflicts 被聚合为一个 DisputedFact。只有当所有来源的 issuer/date/version evidence 一致且存在唯一严格最大来源时，系统才产生 advisory proposal；adoption 与 reopen 均为显式、可审计操作。

**图 3：** 在相同 C1 full scenario 上，C2-B4 将 LLM 调用从 48 降至 9，并降低 Token 与检测时延。该结果为固定受控场景的真实服务成本消融。

**图 4：** 在 12 个构造的 synthetic holdout fact families 上，C4.6 global proposal 与简化 baseline 的比较。每个 fact family 只有在全部三次 independent replicates 正确时才计为正确；该图不是真实业务文档准确率。

**图 5：** explicit adoption / durable reopen 的 fail-closed 状态机。任何 metadata、snapshot、member topology 或 target state 不匹配均返回 HTTP 409 且不产生 mutation。

## 3. 统一视觉规范

建议所有图保持：

```text
画布：白底，横向 16:9 或 A4 双栏宽度
字体：Noto Sans CJK SC / 思源黑体 / Microsoft YaHei
主文字：深蓝 #17324D
claim / architecture：蓝 #2878B5
metadata / proposal：青绿 #1E9E89
explicit action：橙 #ED8A19
fail-closed / unsafe：红 #D95D54
reopen / durable record：紫 #7664C5
```

避免：

```text
3D 图标、人物、拟物化数据库、复杂渐变、过多阴影、彩虹色、长段落文字、无法编辑的截图。
```

优先使用：

```text
圆角矩形 + 清晰箭头 + 少量图标 + 可读的标签 + 数据来源/范围脚注。
```

## 4. IEEE English redraw prompts (GPT / image model)

Use these **only** for schematic figures (Figs. 1, 2, 5). For Figs. 3 and 4, prefer the Python SVG script: image models distort bar heights. If you still need a sketch, the chart prompts are at the end of this section.

Shared constraints for every prompt. Paste them first, then one figure prompt.

```text
IEEE conference figure for two-column insertion. English only. No title inside the image (LaTeX caption exists). White background, flat 2D vector schematic, tight layout, almost no unused margin. Aspect ratio 2.35:1, as if 7.16 inches wide and 3.05 inches tall. Helvetica or Arial. Body labels 8–9 pt equivalent, secondary labels 7 pt. Thin 1.0–1.25 pt strokes. Corner radius 4 px. No 3D, no people, no photos, no icons of computers/clouds/brains, no drop shadows, no gradients, no glow, no decorative illustrations, no watermark, no outer frame around the canvas. Limited palette: ink #17324D, muted #5F6B7A, blue #2878B5, teal #1E9E89, orange #ED8A19, purple #7664C5, red #D95D54, fills 12% opacity of the same hues. One row of boxes unless a second row is required. Short labels, 1–3 lines max per box. Arrows are simple polylines with small filled triangular heads. Print-safe: every color also has a text label so grayscale still works.
```

1. Documents — pale gray. Label: "Versioned docs / wiki". Sub: "PDF DOCX MD".
2. C1 Extract — pale blue. Label: "C1 claim extract". Sub: "subject · predicate · value · quote".
3. Candidates — two stacked half-height boxes feeding one arrow: top "Exact ClaimKey"; bottom "Semantic fallback".
4. C2 Cascade — pale blue. Label: "C2 rules + grounded LLM". Sub: "raw chunk-pair conflict".
5. C4 Cluster — pale blue. Label: "DisputedFact cluster". Sub: "sources · values · members".

Right of stage 5, a compact vertical stack of three smaller boxes:
- teal "C4.6 proposal (advisory)"
- orange "C4.7 adopt (explicit)"
- purple "C4.8 reopen (durable)"

A thin gray bar under the whole pipeline, height 28 px, labeled "Postgres: claims · detection_runs · conflicts · disputed_facts · adoptions".

One red footnote, 7 pt, bottom-left, single line:
"proposal ≠ adopt · adopt ≠ delete · reopen ≠ auto-readopt"

Do not add a figure title. Do not add logos. Keep total height compact.
```

- "S1  value=100  issuer A  v1"

```

### Fig. 5 — fail-closed state machine

```text
Compact left-to-right state machine, four states in one row, diamonds only 36 px tall.

States (rounded rectangles):
1. Blue "Pending" — members pending, chunks on
2. Teal "Proposal" — advisory winner + snapshot
3. Purple "Adopted" — winner on, losers off, durable record
4. Blue "Reopened" — pending again, record revoked

Decisions (small diamonds):
D1 between 1 and 2: "unique max + consistent metadata?"
D2 between 2 and 3: "explicit adopt, snapshot match?"
D3 between 3 and 4: "explicit reopen, record match?"

YES arrows go forward. From Reopened a dashed arrow returns under the row to Pending.

NO arrows all go down to one shared red box spanning the bottom:
"HTTP 409 · no mutation
(no proposal / stale / topology change / target mismatch)"

D1 NO also labels "abstain". No other text. No legend. No title. Keep vertical size under 2.4 inches at 7.16 in width.
```
