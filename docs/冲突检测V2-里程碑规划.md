## 1. 现状小结（改动的出发点）

当前 M3 实现是**块对（chunk-pair）粒度的两级流水线**：

```
上传完成 (knowledge_process.go:706)
  → asynq 任务 conflict:detect (QueueConflict, WorkerPoolEnrichment)
  → 粗筛：每个新 chunk 以自身内容做 HybridSearch（阈值 0.4，top-8）
       knowledge_conflict.go: coarseFilterBySearch
  → 去重 pending 对 → LLM 逐对裁决（temp 0.1，单对单调用，三分类 JSON）
       knowledge_conflict.go: fineAdjudicate / adjudicatePair
  → 写 knowledge_conflicts 表（pending）
  → 检索期：PluginConflictPenalty 对 pending 冲突块 ×0.6 降权
  → 人工裁决 Resolve → 禁用败方 chunk / 触发 wiki 重摄取
```

已识别的结构性短板：

| # | 短板 | 根因 |
|---|------|------|
| S1 | 相似 ≠ 同一事实：误配对烧 LLM、跨表述真冲突漏召回 | 粗筛只有整块 embedding 相似度 |
| S2 | 定位不到"哪条声明"矛盾；跨 chunk 组合矛盾检不出 | chunk 粒度太粗 |
| S3 | 成本 O(chunks×topK) 全走 LLM，误报防御全靠 prompt 军规 | 无廉价前置过滤层、无批处理 |
| S4 | version_update 全靠 LLM 从内容猜 | 不利用文档日期/版本/来源元数据 |
| S5 | 同一争议事实生成 N 条独立 pending，人工裁决 N 次 | 冲突不聚类 |
| S6 | 存量语料内部矛盾永不被发现；裁决失败静默跳过 | 只有"新对旧"单向检测，无巡检 |
| S7 | 争议过程在 wiki 上不可见：裁决后仅靠 `triggerWikiReingestForDisabledChunks` 重摄取"冲掉"败方内容；用户对 wiki 的修改不参与冲突审查 | wiki 是下游产物，不是一等知识源 |

V2 核心思路：
1. **冲突的基本单位从 chunk 对改为"同一事实槽位上的互斥取值"（声明级）**；
2. **Wiki 是维护重心**：冲突/裁决以用户可见方式写回 wiki；wiki 内容（含用户编辑）
   与文档同等参与冲突检测；判别结果最终收敛回 wiki。

### 1.1 写回架构决策（两条腿）

| | 争议块（结构化状态） | 正文叙事整合 |
|---|---|---|
| 执行者 | 确定性管线（模板渲染） | agent（提案-校验-应用） |
| 理由 | 事实记录必须幂等、可重放、字段级精确、零 token、免疫 prompt 注入 | 上下文相关改写（同页多处旧值表述、关联页传播）只有 LLM 能做 |
| 身份 | `EditSource=pipeline` | `EditSource=agent`（高置信自动）/ 人工审计队列（低置信） |

**环路防断**（wiki 写回 → 触发重抽 → 再检出 → 再写回 的死循环）：
- 仅 `EditSource=user` 的 wiki 编辑触发声明重抽；`pipeline/agent/revert` 不触发；
- 争议块标记区内的内容永不参与声明抽取。

**权威性政策**（用户改 wiki 与源文档矛盾时谁赢）：KB 级配置
`wiki_authority_policy: wiki_wins | doc_wins | always_adjudicate`，默认 `always_adjudicate`。

### 1.2 争议块标记规范（草案）

由确定性管线写入/替换，锚定 `id`（DisputedFact ID），幂等更新：

```markdown
<!-- weknora:dispute id=df-8f3a status=pending claim_key=报销上限@差旅政策 -->
> ⚠️ **争议待裁决**：报销上限
> - 《差旅政策v2.pdf》称：**5000 元/月**（2026-06 生效）
> - 《员工手册.docx》称：**3000 元/月**
> [前往裁决](/kb/{kbId}/conflicts/df-8f3a)
<!-- /weknora:dispute -->
```

裁决后同一块被替换为结论态：

```markdown
<!-- weknora:dispute id=df-8f3a status=resolved resolution=newer_wins resolved_by=张三 resolved_at=2026-08-21 -->
> ✅ **已裁决**：以《差旅政策v2.pdf》为准，上限 5000 元/月。
> ~~旧值 3000 元/月~~ 已被取代（superseded）。
<!-- /weknora:dispute -->
```

约束：标记区不参与声明抽取与 wiki 检索索引加权；agent patch 不得触碰标记区。

### C4 争议事实聚类 + 争议块写回（v2 扩容）

> **v6 实现状态**：C4-Lite 的 `DisputedFact` 聚类、raw conflict anchor、API 重建/导出和
> 三值同事实实验已实现，待真实服务验证；详见
> [`冲突检测V2-C4-Lite-技术设计.md`](冲突检测V2-C4-Lite-技术设计.md)。
> 下方争议块写回、cluster 级裁决传播和前端重构仍为后续扩展，不阻塞 C4-Lite。

**目标**：
1. 同一声明键下的所有冲突聚合为一个 `DisputedFact`（N 个来源、M 个候选值），人工裁决一次、判定传播至所有关联 pair；

### C7 agent 叙事整合（新增）

**目标**：裁决落定后,由受限 agent 将结论**整合进 wiki 页面正文**（争议块之外的部分）：
定位同页所有受影响表述（含换算/转述）、改写为胜方值并挂 supersession 标注、检查关联页
（链接页/父级摘要页）是否需要传播、生成符合页面行文的过渡说明。采用
**提案（diff patch）→ 确定性校验 → 应用/审计** 三段式,不允许 agent 直接写页面。

```
输入：裁决结果 + 受影响页面（claim 溯源定位）+ 关联 claims
agent 工具集（受限）：read_page / list_related_pages / propose_patch(diff)
校验器（确定性）：
  - patch 不得触碰 weknora:dispute 标记区
  - 不得删除 SourceRefs / 修改 frontmatter
  - 改动句与裁决结论做 NLI 一致性检查（entail 才放行）
  - 单页 patch 规模上限（防大面积重写）
应用：校验通过且置信 ≥ 阈值 → 自动应用（EditSource=agent，落 revision 可回滚）
      否则 → patch 提案进人工审计队列
```

| 改动 | 位置 | 新/改 | 预估 |
|------|------|------|------|
| 迁移：`wiki_patch_proposals` 表（patch 全文、状态 pending/applied/rejected、置信度、校验报告） | `migrations/versioned/000089_*`、`migrations/sqlite/000010_*` | 新 | ~90 SQL |
| types + 仓储 | types + interfaces + repository | 新 | ~240 |
| 整合 agent 服务（prompt、工具循环、patch 生成；复用 internal/agent 基建） | `internal/application/service/wiki_integrate_agent.go` | 新 | ~400 |
| patch 校验器（标记区保护、SourceRefs 保护、NLI 一致性、规模上限） | `internal/application/service/wiki_patch_validator.go` | 新 | ~220 |
| 触发挂钩（cluster Resolve 完成事件 → 入队 `wiki:integrate` 任务） | `knowledge_conflict.go` + task 注册 | 改 | ~70 |
| API：patch 提案列表 / 批准 / 拒绝 | handler + routes | 新 | ~110 |
| 前端：审计队列页（diff 视图、批准/拒绝）、KB 配置置信阈值 | 新组件 + 4 语言包 | 新 | ~280 |
| 单测：校验器规则矩阵、置信分流、回滚路径 | | 新 | ~250 |

**验收标准**
- 预设场景（同页 3 处旧值表述 + 1 个关联页）：agent patch 覆盖 ≥2/3 处正文表述且改写正确；
- 校验器拦截：触碰争议块 / 删 SourceRefs / NLI 不一致的 patch 100% 被拒；
- 低置信 patch 进审计队列,批准后应用、拒绝后无副作用；应用后可通过 revision 回滚；
- **agent 写回不触发声明重抽（环路防断回归,与 C1 联测）**。

**风险与缓解**
- agent 悄悄改错数字（中高,最难发现的失败模式）→ NLI 校验 + 数值白名单校验（patch 中出现的数值必须 ∈ {胜方值, 原文其他无关数值}）+ 默认低阈值多进审计；
- prompt 注入经由文档内容传导 → agent 输入只含裁决结论与页面内容,不含原始文档全文；工具集无任何库外写能力；
- 成本 → 仅裁决事件触发,天然低频。
