# 真实企业文档：原生 DocReader 观测实验

这是一条**无标注、可运行**的研究原型链路。它把私有文件夹里的原文件经 WeKnora 公开 multipart API 交给 **DocReader 解析**，再走 claim extract → conflict detect → DisputedFact rebuild。

它**不是**准确率评测，不要和 synthetic policy、WikiFactDiff/VitaminC 数字池化，也不要写成真实业务文档 / 人类审核准确率。

默认入口：

```text
~/weknora-private-corpus/docs/standard-product
```

产物必须留在仓库外。脚本不把正文写进 Git。

## 2. 生成无标注场景（不上传）

先只扫文件名 / 大小 / SHA-256，选出最多 8 个去重文件。优先文件名版本族（如 `*_v1` / `*_v2`），否则取较大文件。默认跳过 `<1KB` 和 `>20MB`。

```bash
cd ~/weknora

DOC_ROOT="$HOME/weknora-private-corpus/docs/standard-product"
PLAN="$HOME/weknora-private-corpus/native-standard-product"

make experiment-native-plan \
  DOC_ROOT="$DOC_ROOT" \
  OUTPUT="$PLAN" \
  MAX_FILES=8 \
  OVERWRITE=1
```

看：

```text
$PLAN/native_eval_scenario.json
$PLAN/selected_documents.csv
$PLAN/plan_summary.json
```

`ingest_mode=file`。标题不用文件名伪造发布机构/日期/版本；全局胜方建议只认文档 header 里的显式字段，多数企业文档会 abstain，这是预期行为。

加大样本只改 `MAX_FILES`，例如 `20`。不要一次上传整个目录。

## 3. 真实上传 + 原生解析

```bash
cd ~/weknora

RUN="$HOME/weknora-private-corpus/runs/standard-product-smoke"

make experiment-native-eval \
  SCENARIO="$HOME/weknora-private-corpus/native-standard-product/native_eval_scenario.json" \
  OUTPUT="$RUN" \
  FILE_UPLOAD_TIMEOUT=300 \
  TIMEOUT=600 \
  CLAIM_TIMEOUT=600 \
  CONFLICT_TIMEOUT=900
```

每份原文件走：

```text
POST /knowledge-bases/:id/knowledge/file
  → DocReader 解析
  → claim:extract
  → conflict:detect
  → disputed-fact rebuild
```

默认 variant 是接地级联 `c2-batch`。只要观测、更省调用可加 `VARIANT=c2-rules`。

若某份 PDF/DOCX 解析失败，run 会停在该文件并写 `$RUN/failure.txt`。不要改原文件内容去“洗数据”；可从 `selected_documents.csv` 去掉该行后重生成 plan，或先用 `MAX_FILES=3` 缩小。

若已经跑完一局，**不要为了对齐文档级 claims 而重跑**。拉取后对同一 run 再汇总即可：文档级计数改从 `claims.json` 重算。

```bash
cd ~/weknora
git pull --ff-only origin arena/01a01e71-weknora
make experiment-native-summarize \
  RUN="$HOME/weknora-private-corpus/runs/standard-product-smoke"
```

## 5. 这轮能回答什么 / 不能回答什么

能：

- 这些真实 PDF/DOCX 能否被 DocReader 解析
- 能否抽出 claims
- 同一临时 KB 里会不会出现 raw conflict / DisputedFact
- 有没有 dead letter

不能：

- 真实业务准确率
- 人类审核 kappa
- 原生 header 抽取准确率
- 与 synthetic holdout 或公开评测池化后的总准确率

若以后要做带 gold 的版本治理评测，再走人工选材 / 核实 header 的 labeled corpus 协议，不要把本观测 run 事后改写成 holdout 准确率。
