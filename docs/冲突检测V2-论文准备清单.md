## 1. 结论先行：现在能不能开始写？

**可以现在开始写论文草稿；尚不建议现在投稿。**

当前已经足以写：

```text
问题定义 / 威胁模型

C4 fact clustering
```

但 Results/Abstract 中暂时只能做如下主张：

```text
在 controlled policy corpus 中，系统通过真实 HTTP API、Asynq、PostgreSQL 和配置模型运行；
它能够输出/拒绝 global winner proposal，并执行显式 adopt/reopen 的 fail-closed 生命周期。
```

```text

显著降低真实人工时间
已解决所有 schema drift / authority hierarchy / version semantics
provider RNG seed 已受控
```

## 3. 三层论文门槛

### 3.1 Draft-ready：现在即可开始

满足条件：

- [x] 研究问题清晰：chunk-pair conflict 无法安全表达多来源、版本化事实争议；
- [x] 技术贡献可描述：claim anchor、cascade、fact cluster、global proposal、explicit adoption/reopen；
- [x] 可重复的真实服务实验脚本；
- [x] controlled matrix 与安全负例；
- [x] C4.9 15 个 detector run 的 dead-letter 分布后验确认（15 × 0）。

可完成论文的：

```text
Introduction
Related Work
Method
System Design
Controlled Evaluation
Limitations
```

### 3.2 Workshop / pilot-ready：建议最低投稿门槛

建议至少准备：

```text
30–50 个事实家族（DisputedFact-level）
≥15 个明确 global-winner 正例
≥15 个 no-proposal / ambiguous 负例
每个正例尽量 ≥3 个来源
按 fact_family_id 做 development / holdout 隔离
holdout 至少 15–25 个事实家族
```

标注要求：

```text
两位独立 reviewer 覆盖所有 holdout case
记录 issuer/date/version 原始证据
记录 expected winner 或应 abstain 的原因
disagreement 必须仲裁
报告 exact agreement 与 Cohen's kappa
```

建议目标：

```text
holdout winner/no-proposal policy accuracy：给出 95% CI
unsafe action：0（所有 stale/no-proposal/ambiguous negative）
Cohen's kappa：优先 ≥0.70；若低于此值，报告原因与仲裁协议
```

这足以支撑 workshop、demo、短论文或内部研究稿，前提是论文把结论限定为 pilot study。

### 3.3 Full-paper-ready：考虑正式 conference / journal

建议至少：

```text
100+ facts，按事实家族去重
多个版本场景与多个领域/文档类型
至少 3-source 的正例占有足够比例
cross issuer、metadata missing、date/version disagreement、tie、interval overlap 等负例
独立 development / validation / holdout，严禁同一 source document 跨 split
```

实验必须包括：

1. **Detection / cost baseline**：V1、C1、C2-Rules、C2-B4；calls/tokens/latency/integrity；
2. **Clustering baseline**：raw chunk-pair review vs DisputedFact clustering；
3. **Winner baseline**：latest-upload、date-only、version-only、raw-pair local C3 vote、C4.6 global rule；
4. **Safety baseline**：stale action、no proposal、partial member、shared chunk / reopen rejection；
5. **Human study**：双审阅、仲裁、一致性、错误 taxonomy；
6. **Statistics**：按 fact family（不是 raw row）报告 95% bootstrap CI；必要时 paired test；
7. **Reproducibility**：commit、模型配置、scenario manifest、artifact schema、许可/匿名化说明。

Full-paper 的重要不是“100”这个数字，而是：证据规模与论文主张匹配、split 无泄漏、人工 ground truth 可审计。

## 4. 推荐的论文主张边界

一个稳妥的论文中心主张可以是：

> 我们提出面向版本化多来源知识库的事实级冲突治理原型：从 raw chunk-pair conflict 聚为 DisputedFact，
> 在显式 issuer/date/version evidence 下提出全局 winner，并通过 optimistic、可撤销的 API 生命周期避免
> 将局部 A/B 方向误用为全局 side effect。

可以用证据支持的子主张：

```text
C2 批量 cascade 减少 LLM 调用/成本
C4 减少重复人工裁决单元
C4.6 不会因 issuer mismatch、signal disagreement 或 tie 强行选择 winner
C4.7/C4.8 会对 stale/no-proposal/no-active state fail closed
out-of-order ingest 不改变 global winner
```

不能在当前阶段主张：

```text
全自动知识治理
真实生产用户效率提升
对所有版本/权威性关系的普遍适用
无需人工 review 的正确性
```

```text
第 6 步（可选升级）：若要主张真实泛化，再用 C4.10 inventory/selection/materialize 建有许可的真实 fact-family corpus
第 7 步（可选升级）：两位 reviewer 独立标注真实 holdout，并进行仲裁、agreement、Cohen's kappa 与 95% CI
```

建议在第 1 步启动时就写论文草稿；不要等所有实验结束才开始写。Method、architecture figure、C2/C4 controlled
results 和 limitations 可以并行完成，真实 holdout 数据完成后再锁定 Abstract、Results 表格和结论措辞。

## 6. Go / no-go checklist

在决定“可以开始投稿”前，至少逐项回答：

- [ ] 我们的主张是 controlled-system claim，还是 real-corpus generalization claim？
- [ ] 每个 holdout fact family 都没有出现在 development/calibration 中吗？
- [ ] 数据来源、许可、匿名化和保存期限可写入论文吗？
- [ ] 两位 reviewer 的原始 sheet、仲裁记录和 agreement 是否保留？
- [ ] 所有失败 case、HTTP 409 safety rejection、dead letters 是否保留并报告？
- [ ] winner/no-proposal metrics 是否按 fact family 而非 raw pair 计算？
- [ ] 是否报告 abstention/no-proposal，而不是只报告“选对 winner”的子集？
- [ ] 是否把 C4.9 的 independent replicates 明确写成无 seed control？
- [ ] 是否避免将实验 KB 中的 chunk disable 直接叙述为生产侧知识删除？

若前六项都能回答“是”，可以认真考虑 workshop/pilot 投稿；若再完成 full-paper-ready 的规模、baseline 和
holdout 条件，则可考虑更高要求的正式投稿。
