## 1. 结论

C1 已从“代码可编译”推进到**真实服务、真实异步队列、真实模型、真实数据库**上的
可复现实验基线。以下链路均在实际运行环境中验证：

```text
Markdown 文档注入
→ chunking
→ claim:extract
→ claims 持久化
→ claim-key / fallback 候选生成
→ claim-conditioned LLM fine adjudication
→ knowledge_conflicts 持久化
→ 审计导出、人工复核、gold-v2 candidate 与 dual-scope 指标
```

**C1 的最终研究口径**：

| 口径 | Precision | Recall | 状态 |

## 4. gold-v2 与 dual-scope 决策

### 4.1 证据链

9 条 `gold_missing_claim` 已物化为 full gold-v2 candidate：

```text
quote_source = review_quote
quote_match  = exact
```

每条新增事实有：

```text
source_audit_row_id
review_note
verbatim quote
candidate gold ID
```

完整 gold-v1 不被修改；所有 candidate、provenance、scope review 位于实验运行
artifact 中。候选集应经独立第二审阅者确认后，才推广为仓库的受版本控制 `gold-v2`。

### 4.2 broad-maintenance vs narrow-conflict-critical

采用双口径，避免“所有真实 wiki 信息”与“直接冲突关键事实”混为一个指标：

| 处理 | 数量 | 规则 |
|---|---:|---|
| broad 独立新增保留 | 7 | source-grounded，适合 wiki / maintenance |
| narrow 独立新增保留 | 3 | 会直接形成状态、数值、日程、安全效果等冲突 |
| 合并 | 1 | `引发幻觉` 合并至更具体的 `导致极度幻觉` |
| 排除 | 1 | 纯别名 `StarQuartz` 不进入本轮 gold |

最终：

```text
broad gold-v2:   63 + 7 = 70 claims，covered 59
narrow manifest: 12 + 3 = 15 claims，covered 15
```

## 5. 输出卫生与后续最小修复

当前 raw output 的实际卫生问题：

```text
5 duplicates（含 scope review 合并的一项）
3 low-value / excluded facts
1 genuine FP
```

这说明 C1 的下一轮不应再做大范围 prompt 重写；优先做：

1. **确定性去重**：同 source / 同稳定槽位 / 语义相同值的 claims 合并；
2. **可配置低价值过滤**：别名、纯代号、非冲突元数据进入 broad wiki 与否由策略决定，
   不自动进入 narrow 冲突评估；
3. 为 11 个 `genuine_fn` 建立小型回归用例，而非继续只在 6 文档开发集上调 prompt。

## 6. 研究有效性与限制

1. `testdata/claims_eval` 已用于 normalizer、prompt、fallback 与裁决校准，属于
   **development/calibration corpus**，不应作为最终唯一论文测试集；
2. 当前人工审计为单审阅者。论文主结果应对 gold-v2 additions 及至少一部分
   schema-equivalent links 做第二审阅者复核，并报告 agreement；
3. narrow conflict-critical precision 未测，因为还未给每一条 raw prediction 完整标注
   critical/non-critical；当前应只报告 narrow Recall；
4. candidate gold-v2 的 human-adjusted 指标应明确标为“人工审计校正”而非纯自动 benchmark；
5. 当前 `knowledge_conflicts` 仍是 chunk-pair 粒度，同一逻辑事实可出现多条 raw pair，
   这是 C4 `DisputedFact` 聚类的明确研究输入，不应在 C1 阶段掩盖。
