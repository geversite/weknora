\section{课题来源及研究的目的和意义}

% TODO：若实际为导师纵向课题/企业横向课题，请替换为课题名称与编号
本课题为自选课题，结合导师在企业知识与检索增强生成方向的研究积累，以及 WeKnora 开源社区在企业知识库落地过程中暴露的真实需求提出。

\subsection{研究背景}

随着大语言模型（Large Language Model, LLM）能力的快速提升，检索增强生成（Retrieval-Augmented Generation, RAG）已成为企业知识管理的主流技术范式：企业将内部文档构建为知识库，通过"检索—增强—生成"管线实现私有领域知识的准确问答与推理。以本课题所依托的 WeKnora 开源框架为例，其已支撑文档解析、混合检索（BM25 稀疏召回 \cite{robertson2009} / Dense 稠密召回 / GraphRAG 图谱增强）、ReAct Agent 多步推理 \cite{yao2023}、自动 Wiki 蒸馏等完整能力链，覆盖了企业知识管理的核心场景。

然而，当前 RAG 研究与工程实践普遍建立在\textbf{静态语料假设}之上：即假设知识库内容是准确、一致、不变的，研究的重心放在检索精度（召回率、重排质量）与生成质量（忠实性、引用准确性）上。真实企业环境中，这一假设难以成立：

\textbf{（1）知识冲突普遍存在。}企业知识库持续接收来自不同部门、不同时期、不同版本的海量文档，文档之间存在大量事实性矛盾：政策口径调整导致新旧规定不一致（如退货政策从 7 天调整为 15 天）、同一产品参数在不同手册中的记载冲突、文档过时但未被替换等。已有研究与系统初步观察表明，当检索命中互相矛盾的证据时，现有 RAG 系统往往盲从其中一方，或生成貌似折中的"调和式"回答，产生难以察觉的幻觉，直接威胁企业知识服务的可信度。

\textbf{（2）知识随对话流失。}用户在与知识库的交互中会自然地提供增量信息（补充、更正、本地化事实，如"我们公司实际部署的是混合检索方案"）。现有系统将对话视为一次性消费，增量知识随会话结束而流失，知识库无法从使用过程中演化。已有的 LLM 记忆研究多面向 Agent 私有记忆，缺少面向组织级知识资产的沉淀机制及其风险控制。

\textbf{（3）知识资产缺乏"使用—质量"反馈信号。}哪些文档被反复引用、哪些从未被使用、哪些内容处于未裁决的争议状态，这些信号对知识库的质量治理与检索排序均有价值，但在现有系统中普遍缺失。

\subsection{问题提出}

综上，围绕将企业知识库从"只读资料库"升级为"可维护、可演化、可观测的知识资产"这一总需求，本课题的核心科学问题可概括为：\textbf{在知识库内容非一致且持续演化的前提下，如何保障检索增强生成的可信性？}该核心问题沿知识生命周期分解为三个方法子问题与一个系统支撑问题：

\begin{enumerate}
  \item \textbf{问题一（冲突检测与消解——存量一致性）}：如何在成本可控的前提下，检测大规模语料中跨文档的事实矛盾，区分"事实矛盾、版本更新、互补共存"等关系，并通过人机协同裁决维护知识一致性？
  \item \textbf{问题二（冲突感知生成——可信使用）}：当检索证据内部存在矛盾时，大模型的生成行为如何？如何设计冲突感知的检索与生成策略，使系统忠实呈现分歧而非盲目站队？
  \item \textbf{问题三（知识持续演化——增量一致性）}：如何从用户对话中识别值得沉淀的增量知识，决策"何时写入、写到何处、如何写入"，在知识沉淀收益与噪声污染风险之间取得可量化的平衡？
  \item \textbf{问题四（系统支撑）}：上述能力的观测基础（引用信号）、组织基础（层次化治理）如何在真实系统上端到端落地并验证？
\end{enumerate}

\subsection{研究的目的及意义}

\textbf{理论意义}：
\begin{enumerate}
  \item 将企业场景下多文档间的事实冲突检测形式化为"语料级冲突对发现问题"，补充现有知识冲突研究（集中于参数知识与检索证据冲突）的空白；
  \item 提出并评测"知识写入决策"问题（when / where / how）及"沉淀率—污染率"权衡框架，为 LLM 记忆与知识库演化研究提供新的问题定义与评测协议；
  \item 系统刻画大模型在"检索证据内部互相矛盾"条件下的生成行为模式，深化对 RAG 忠实性的理解。
\end{enumerate}

\textbf{应用价值}：研究成果可直接落地于企业知识管理系统，解决知识库一致性维护、对话知识沉淀、知识资产治理等实际痛点。本课题依托的开源框架与已实现的原型系统为成果转化提供了直接通道。

\section{国内外在该方向的研究现状及分析}

\subsection{检索增强生成与知识库组织}

RAG 自 Lewis 等人提出以来已成为 LLM 知识外置的主流方案 \cite{lewis2020}。围绕检索质量与生成可信性，近年涌现大量改进：Self-RAG 通过反思令牌实现按需检索与自我批判 \cite{asai2024}；CRAG 引入检索质量评估与纠错机制 \cite{yan2024}；GraphRAG 利用实体图谱增强全局性问答 \cite{edge2024}；RAPTOR 构建递归摘要树以支持跨粒度检索 \cite{sarthi2024}；HippoRAG 借鉴海马体记忆索引理论设计个性化 PageRank 检索 \cite{gutierrez2024}。国内学界对 RAG 的评测体系、中文场景适配亦有系统性综述 \cite{gao2023}。

在企业知识组织方面，层次化摘要索引（RAPTOR、GraphRAG 社区摘要）多依赖自动聚类生成索引结构，对人类既有组织语义（目录、文件夹、产品线）的利用研究较少，且普遍缺乏索引的\textbf{增量维护}与\textbf{使用信号反馈}机制。

\textbf{评述}：现有 RAG 研究将知识库视为静态、一致的外部记忆，聚焦"给定语料如何检索生成"，对"语料本身质量如何维护、如何演化"关注不足。

\subsection{知识冲突研究}

知识冲突研究可分为四条线：

\textbf{（1）参数知识与检索证据的冲突。}Longpre 等人较早研究实体知识冲突对问答的影响 \cite{longpre2021}；Mallen 等人分析模型何时应信任参数知识 \cite{mallen2023}；Xu 等人（EMNLP 2023）系统刻画了 LLM 在参数知识与检索证据冲突时的"盲从"与"固执"行为 \cite{xu2023}；ConflictQA 进一步构建了该方向的评测基准 \cite{xie2024}。此类工作冲突的双方是"模型内部知识"与"外部证据"。

\textbf{（2）知识时效。}FreshLLMs / FreshQA 针对世界知识过时问题评测搜索增强能力 \cite{vu2024}，但其关注"证据新于参数"，而非语料内部的矛盾。

\textbf{（3）语料内部矛盾。}维基百科矛盾句检测、多文档摘要中的事实一致性校验（如 Fool Me Twice 基准 \cite{zhong2021}）等工作局限于句子级分类或摘要忠实性；生成端方面，WikiContradict 基准基于维基百科编辑标注的真实矛盾构建了 253 个人工标注样本，系统评测了主流 LLM 在双矛盾证据下的回答行为，发现模型普遍难以完整呈现分歧 \cite{hou2024wikicontradict}，但其语料限于维基百科、定位为生成端评测，未涉及冲突的\textbf{检测与消解管线}，也缺少企业场景中密集的版本更替类别。

\textbf{（4）多源真值发现（Truth Discovery）。}数据库与数据挖掘领域较早关注"多源冲突信息中判定何者为真"的问题 \cite{yin2008}，后续发展出考虑源可信度的系统性方法与综述 \cite{li2015}。该方向假设观测可结构化为"源—对象—取值"三元组，与本课题面向非结构化自然语言文档、需语义级比对的设定不同，但其源可信度估计思想对冲突裁决具有借鉴意义。

\textbf{评述}：知识冲突的学术热点集中在参数 vs.\ 证据 \cite{xu2024survey}；语料内部冲突近期开始受到关注（如 WikiContradict），但仍缺乏面向企业场景（版本更替密集、口径多样）的\textbf{检测端}基准，以及覆盖"检测 $\rightarrow$ 裁决 $\rightarrow$ 检索降权 $\rightarrow$ 生成呈现"全链路的端到端方法；真值发现提供了裁决侧的经典思想，但难以直接处理非结构化文档。

\subsection{LLM 记忆与知识库演化}

MemGPT 将操作系统的分页思想引入 LLM 记忆管理 \cite{packer2023}；MemoryBank 引入遗忘机制；A-MEM 提出 Agentic Memory 实现记忆的动态组织 \cite{xu2025amem}；Mem0 进一步将记忆写入建模为 LLM 对 ADD / UPDATE / DELETE / NOOP 四种操作的决策，在个体记忆场景取得了成本与延迟优势 \cite{chhablani2025}，其"写入即决策"的思想与本课题的知识写入决策相近，但面向 Agent 个体记忆且允许覆盖式更新，不涉及组织级资产所需的审计与回滚约束；Generative Agents 中的记忆流支持反思与检索 \cite{park2023}。自演化（self-evolving）方向的综述总结了 LLM 从经验中自我改进的各类范式 \cite{tao2024}。知识编辑（ROME、MEMIT 等）研究参数级知识的定位与修改 \cite{meng2022}，与本课题的语料级更新互补。

\textbf{评述}：现有记忆研究面向\textbf{Agent 个体记忆}，强调"记住交互历史"；本课题面向\textbf{组织级知识资产}，强调"从交互中沉淀可复用、可审计、可回滚的知识"，二者在问题定义（组织级写入决策 vs.\ 个体记忆管理）、风险约束（污染防护与审计回滚 vs.\ 遗忘与冗余）、评测协议（下游净增益 vs.\ 记忆召回）上均有本质差异。对话驱动的知识库演化目前缺少系统方法与评测基准。

\section{学位论文的主要研究内容、实施方案及其可行性论证}

\subsection{主要研究内容}

本课题的研究主线可概括为：\textbf{面向"非一致、持续演化"的企业语料，构建可信的检索增强生成能力}。研究内容沿知识生命周期展开并相互衔接：研究内容一治理存量语料中的事实冲突（一致性的\textbf{存量治理}），研究内容二保障冲突证据下的可信生成（一致性的\textbf{可信使用}），研究内容三从对话中沉淀增量知识并控制污染（一致性的\textbf{增量演化}），三者横向协同，共同支撑研究内容四的系统实现与端到端验证（观测与组织底座）。总体框架如图~\ref{fig:framework} 所示。

\subsubsection{研究内容一：多文档知识冲突检测与消解方法}

\textbf{目标}：在成本可控前提下，检测同库跨文档的事实矛盾并支持人机协同消解。

\textbf{具体内容}：
\begin{enumerate}
  \item \textbf{任务形式化}：将语料级冲突检测定义为——给定文档集合 $D$ 及其 chunk 集合 $C$，找出所有冲突对 $(a,b) \in C \times C$ 并分类为\{事实矛盾、局部矛盾、版本更新、非冲突\}，优化目标为检测精度与计算成本（LLM 调用次数）的联合最优。其中，\textbf{事实矛盾}指同一实体的同一属性取值互斥；\textbf{局部矛盾}指部分属性互斥而其余信息可共存；\textbf{版本更新}指同一事实取值随时间演替（由时间戳等元数据佐证，属于"应消解但方式特殊"的类别）；\textbf{非冲突}（互补）指表述相近但信息互不矛盾，是检测中最高难度的负样本；
  \item \textbf{两阶段级联检测方法}：第一阶段基于稠密向量检索进行候选对粗筛（语义高相似但来源不同的 chunk 对），第二阶段由 LLM 对候选对精判并输出冲突类型与理由；研究粗筛阈值、候选规模与精度—成本曲线的关系，并探索按候选难度自适应分配精判模型规模的调度策略；
  \item \textbf{冲突分类体系}：区分四类关系是任务难点，引入文档时间戳等元数据辅助版本更新识别；
  \item \textbf{裁决联动机制}：设计冲突记录的状态机（待裁决/保留双方/以新为准/以旧为准/非冲突），裁决结果联动检索端——被裁定过时内容的降权与剔除，形成"检测—裁决—检索"闭环；
  \item \textbf{基准数据集构建}：基于真实文档修订历史与受控扰动合成两条路径构建带标注的企业知识冲突基准，重点构造高难度负样本（语义高度相似但互补的干扰对）。
\end{enumerate}

\subsubsection{研究内容二：冲突感知的检索与可信生成方法}

\textbf{目标}：刻画检索证据内部存在矛盾时 LLM 的生成行为，并提出缓解方法。

\textbf{具体内容}：
\begin{enumerate}
  \item \textbf{行为刻画}：基于研究内容一构建的冲突对构造"命中矛盾证据"的问答集，对多个主流 LLM 在标准 RAG 管线下的回答进行行为分类（正确呈现分歧 / 盲从一方 / 幻觉调和 / 拒答），分析证据顺序（长上下文中位置带来的偏差 \cite{liu2024}）、来源标注、时间戳提示等因素的影响；
  \item \textbf{冲突感知检索}：将工程原型中的冲突降权启发式升级为\textbf{可信度感知排序}——融合来源时效性、冲突状态、历史引用信号（研究内容四）的多维知识可信度模型，研究其对检索质量与下游回答的影响；
  \item \textbf{冲突感知生成策略}：设计对比式证据呈现（结构化呈现矛盾双方及其来源、时间戳）与拒答机制（该拒时拒），并与降权策略组合评测；
  \item \textbf{评测协议}：建立冲突场景下生成质量的自动评测（LLM-as-judge，并做人工校准，报告一致性系数）与人工评测子集。
\end{enumerate}

\subsubsection{研究内容三：对话驱动的知识库持续演化方法}

\textbf{目标}：从用户对话中沉淀增量知识，控制噪声污染风险。

\textbf{具体内容}：
\begin{enumerate}
  \item \textbf{知识写入决策问题定义}：形式化为 (when) 用户消息是否包含值得沉淀的新事实、(where) 应写入知识库哪个位置、(how) 以何种方式写入（增量合并且不破坏原文）的三段决策；
  \item \textbf{两阶段写入管线}：第一阶段轻量判断消息有效性（区分陈述事实与提问/闲聊/观点），第二阶段检索候选页面并规划追加内容；研究两阶段的模型规模分配与成本优化；
  \item \textbf{审计与回滚机制}：所有自动写入附带版本快照与审计标记，支持事后人工复核、回滚与裁决，形成"自动写入 + 事后审计"的风险控制模式；
  \item \textbf{模拟演化环境与评测协议}：构建"种子知识库 + 模拟用户消息流（ground truth 已知）+ 时序回放"的演化环境，定义沉淀率（写入精度、位置准确率、内容忠实度）、下游净增益（反哺后问答正确率提升）、污染率（错误信息入库比例及传染性）、演化曲线（多轮后知识库质量收敛/劣化）四类指标，量化"沉淀—污染"权衡。
\end{enumerate}

\subsection{实施方案及其可行性论证}

\subsubsection{总体方案}

依托 WeKnora 开源框架搭建实验平台，前期四项原型工作（见表~\ref{tab:prework}）已打通"摄入—组织—使用—演化"的核心链路，本课题在此基础上按研究内容逐项开展方法研究与实验验证。\textbf{优先级与裁剪顺序}为：研究内容一、二构成方法主线（必做，分别对应冲突的存量治理与可信使用）；研究内容三在前两者达到预期后开展，必要时收缩为"写入决策 + 审计回滚"的核心实验（保留污染率评测）；研究内容四以工程增量方式伴随全程推进，不单独占用完整实验周期。

\subsubsection{研究内容一的实验设计}

\begin{itemize}
  \item \textbf{数据集}：\textcircled{1} 真实修订历史——采集开源项目文档/产品手册的多版本快照，标注版本更新与跨版本矛盾；\textcircled{2} 受控合成——种子事实句经 LLM 受控改写（数值/否定/时间篡改）注入文档，构造已知 ground truth 的冲突；负样本重点构造"高相似但互补"干扰对；\textcircled{3} 真实语料人工标注测试集——在合成数据之外对少量真实文档 chunk 对进行人工标注，作为外部效度检验，防止方法在合成分布上过拟合。目标规模：数千文档对 / 上万 chunk 对；
  \item \textbf{基线}：embedding 相似度阈值直判（验证"相似$\neq$矛盾"）；句对 NLI 模型（DeBERTa 系，验证传统 NLI 在版本更新类上的局限）；LLM 全量两两精判（验证级联的成本优势）；本课题两阶段级联方法；
  \item \textbf{指标}：冲突对发现 P/R/F1（在构造全集已知的测试集上计算；真实语料上以人工抽检估计召回）、冲突类型分类准确率、LLM 调用次数与 token 成本（精度—成本 Pareto 曲线）、端到端时延；
  \item \textbf{消融}：粗筛阈值扫描、去粗筛层、去时间戳元数据、候选规模 top-k 扫描；
  \item \textbf{分析}：冲突类型混淆矩阵、按难度分层（跨主题/同主题同实体）的性能、真实系统裁决队列的人工纠错比例。
\end{itemize}

\subsubsection{研究内容二的实验设计}

\begin{itemize}
  \item \textbf{数据}：基于研究内容一的冲突对构造 QA 集，确保每个问题命中矛盾证据对；若内容一基准尚未就绪，先基于公开矛盾基准（如 WikiContradict \cite{hou2024wikicontradict}）开展行为刻画，消除关键路径上的串行依赖；
  \item \textbf{对比条件}：标准 RAG（矛盾证据全量入上下文）/ 冲突降权检索 / 冲突感知提示词 / 结构化对比呈现（本方法）/ 干净知识库 oracle 上界；
  \item \textbf{被测模型}：不少于 3 个主流 LLM（如 GPT、Qwen、DeepSeek 系列），结论需跨模型成立；
  \item \textbf{指标}：行为分类分布（正确呈现分歧/盲从/幻觉调和/拒答及其正确性）、LLM-as-judge 忠实性评分（报告与人工标注的 Cohen's kappa，目标 $\geq 0.7$）、证据顺序敏感性分析；
  \item \textbf{消融}：降权因子扫描、有无时间戳提示、有无来源标注。
\end{itemize}

\subsubsection{研究内容三的实验设计}

\begin{itemize}
  \item \textbf{模拟演化环境}：种子知识库（真实文档）+ LLM 生成的模拟用户消息流（含应写入的正例与不应写入的干扰：提问/闲聊/观点/已知信息）+ 多轮时序回放；模拟消息流与真实用户分布的差异作为局限在论文中显式讨论，并以真实系统运行数据交叉佐证；
  \item \textbf{基线}：不反哺 / 无第一阶段过滤的全量写入 / Mem0 式记忆管理直接迁移（将 ADD/UPDATE/DELETE/NOOP 决策用于知识库写入 \cite{chhablani2025}）/ 显式确认模式（模拟用户逐一确认）；
  \item \textbf{指标}：写入决策 P/R、位置准确率、写入内容忠实度、\textbf{下游 QA 净增益}（核心指标：反哺后能否答对原本答错的题）、污染率及其在后续多轮对话中的传染、多轮演化质量曲线、每条消息成本；
  \item \textbf{消融}：第一阶段模型规模、有无已知信息去重、审计回滚对污染的抑制效果。
\end{itemize}

\subsubsection{研究内容四的验证方案}

\begin{itemize}
  \item 端到端功能验证（参考前期里程碑的验收标准体系）；
  \item 真实运行数据采集与分析：全链路追踪下的引用分布、冲突检测误报的人工纠正率、反哺内容被后续引用/回滚的统计闭环；
  \item 系统开销评估：各能力的额外计算成本与延迟影响。
\end{itemize}

\subsubsection{关键技术与难点}

\begin{enumerate}
  \item \textbf{冲突判定精度}（难点）：语义相似与事实矛盾的区分依赖精判模型能力，拟通过冲突分类体系设计、元数据辅助、难度分层负样本训练提示策略缓解；
  \item \textbf{写入决策的噪声控制}（难点）：全自动沉淀的污染风险，拟通过两阶段过滤、挂靠约束（只追加不覆盖）、审计回滚三重防线控制；
  \item \textbf{评测的可信性}（方法论难点）：LLM-as-judge 的偏差，拟通过人工校准子集、多 judge 交叉、一致性系数报告控制；
  \item \textbf{成本约束}：企业场景对 LLM 开销敏感，级联架构与小模型分工是贯穿性优化手段。
\end{enumerate}

\subsubsection{可行性分析}

\begin{enumerate}
  \item \textbf{平台可行性}：依托开源框架 WeKnora，四项核心能力（引用计数、冲突检测、层次治理、用户反哺）已有可运行原型，工程基础扎实，实验可快速开展；
  \item \textbf{技术可行性}：候选粗筛所需的向量检索、精判所需的 LLM 调用、评测所需的追踪体系均已就绪；
  \item \textbf{数据可行性}：冲突基准的两条构建路径（修订历史采集、受控合成）均已验证可操作；模拟演化环境不依赖真实用户隐私数据；
  \item \textbf{风险预案}：若冲突检测精度受限于 LLM 能力，可收缩为"检测 + 人工裁决的人机协同"叙事（精度要求降低，成本叙事保留）；若演化实验污染率过高，其负面结果本身亦构成"沉淀—污染权衡"的发现性贡献。
\end{enumerate}

\section{学位论文预期创新点}

\begin{enumerate}
  \item \textbf{任务与基准创新}：将企业知识库的多文档事实冲突检测形式化为语料级冲突对发现问题，构建面向企业场景、含版本更新特殊类别的冲突检测基准数据集，与面向维基百科、定位生成端评测的现有基准形成互补；
  \item \textbf{方法创新}：提出"检测—裁决—检索"闭环联动的冲突治理机制，设计含难度自适应精判调度的成本高效级联检测方案，给出精度—成本 Pareto 前沿；
  \item \textbf{发现与方法创新}：在企业知识场景下系统刻画大模型在检索证据内部矛盾下的生成行为模式（含"幻觉调和"等现象分类），提出冲突感知的可信度排序与对比式生成策略；
  \item \textbf{问题定义与协议创新}：提出知识写入决策问题（when/where/how）及"沉淀—污染"权衡评测协议，实现带审计回滚的对话驱动知识库演化。
\end{enumerate}

\section{为完成课题已具备和所需的条件、外协计划及经费}

  \item 依托 WeKnora 开源框架及四项可运行原型（引用计数、冲突检测、层次治理、用户反哺），具备完整的实验平台；
  \item 具备主流 LLM API 调用能力（GPT、Qwen、DeepSeek 等系列）及向量检索、全链路追踪等基础设施；
  \item 实验室已有开源项目多版本文档与产品手册等语料资源，可作为基准数据集构建的素材来源。

\textbf{所需条件与外协计划}：本课题以开源框架与公共 LLM API 为主要实验手段，计算资源（GPU）主要用于评测集构建与 NLI 基线微调，拟使用实验室现有服务器或申请学院公共算力；不涉及需外协完成的定制实验设备或数据采购，如遇大规模评测需要，拟与开源社区协作开展众包标注。

\textbf{经费预算}：主要开销为 LLM API 调用费用（评测与合成数据生成）与算力租用，预算规模视评测规模而定，拟通过实验室科研经费与研究生培养经费列支，具体以学院财务规定为准。

\section{预计研究过程中可能遇到的困难、问题，以及解决的途径}

\begin{enumerate}
  \item \textbf{冲突判定精度受限于精判模型能力}：语义相似与事实矛盾在表述层面高度接近，现有 LLM 精判存在系统性偏差。解决途径：设计细粒度冲突分类体系、引入文档时间戳等元数据辅助、构造难度分层的负样本并优化提示策略；若精度仍受限，收缩为"检测 + 人工裁决"的人机协同方案，保留成本优势叙事；
  \item \textbf{全自动知识沉淀的污染风险}：错误写入的知识可能随检索传播放大。解决途径：两阶段过滤前置拦截、挂靠约束（只追加不覆盖原文）、审计回滚形成三重防线；在评测协议中将污染率及其传染性作为核心指标显式度量；
  \item \textbf{LLM-as-judge 评测偏差}：自动评测的可信性存疑。解决途径：设置人工校准子集、多 judge 交叉投票、报告与人工标注的一致性系数（目标 $\geq 0.7$）；
  \item \textbf{成本约束}：企业场景对 LLM 开销敏感，全量两两精判成本不可接受。解决途径：级联架构（粗筛 + 精判）与小模型分工是贯穿性优化手段，以精度—成本 Pareto 曲线为考核指标。
\end{enumerate}
